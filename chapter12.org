- Packets wend their way from host to host, being interpreted and
  inspected and reapeated at each hop, untill they reach their
  destination.
- The *traceroute* program lets you follow packets as they travel
  between hosts, viewing what hosts they pass through to reach their
  destination.
- Microsoft version: tracert

* Our First Traceroute

- Just give the destination server

#+begin_src sh :exports both :eval never-export :results verbatim
traceroute www.google.com
#+end_src

- Each following line is a separete host (router or router like device,
such as firewall). The _gateway in above line is my own router.
- The number at the start of the line is the hop number.
- You see three timestamps: One for each packet sent to the hop. Where
  a single packet might get lost, sending three packets gives a good
  chance of somthing getting through.
- At hop 3, you can see three asteriks. They indicate lost
  packets. Infact in some cases there will be only one or two asterik.

* Traceroute Errors

** Slow Traces

- Traceroute might run very, verly slowly.
- You can run it quickly without dns, using /-n/ option for Unix or
  /-d/ for Windows.

#+begin_src sh :exports both :eval never-export :results verbatim
traceroute -n www.google.com
#+end_src

** starring out

In the above traceroute output, you see something like this:

 #+begin_example
 2  10.201.32.1  6.344 ms  10.352 ms  10.324 ms
 3  * * *
 4  172.19.5.5  10.363 ms  10.527 ms  10.710 ms
 #+end_example

- It seems a single host along the path doesn't respond to traceroute
requests, but hosts beyond it do. You might try from a public
traceroute server to avoid this kind of issue.
- Also some ISPs filter or rate-limit traceroute traffic.

** Time Spikes

- Sometimes you'll see a hop with very high times compares to the
  hosts around it.
- Routers are designed to forward traffic. Responding to traffic
  addressed to the router itself takes more effor than forwarding
  traffic. Router respond to traceroutes and pings at a low priority.

** Time Jumps

- Timestamps might get really high at a certain hop and remaining high
  at all following hops.
- A possible reason for that would be that the traffic is moving
  between continents.

** Multiple Hosts at One Hop

- Sometimes you'll get multiple hostnames at one hop. Each hostname
  gets one or more timestamps.
- Networks can load balance traffic just as servers can. A busy
  connection might have multiple routers. Each will return its own
  traceroute timestamp to the client.

** !Errors

- Sometimes a traceroute ends in an error code like !H or !X.
- !H means that the next host is unreachable. The path is broken.
- !N error means that the entire destination network is unreachable.
- !A, !X or !Z means further communication is administratively
  probhibited.

* Identitying Address and Domain Owners

- whois service can be used for identitying domain owners.

* Asymmetric Routing and Traceroute Servers

- Each router makes its own independent decisions about how to route
  traffic. The resulting mishmash of paths is called asymmetric
  routing. It's simultaneously a key part of how the Internet works.

* Ongoing Traceroute: mtr

- If you want to watch network routse on an ongoing basis, *mtr* (my
  trace route) is available as a package on all operating systems.
- It runs traceroute continously and prints packet and timing
  statistics.

* How Should You Use Traceroute ?

- Good for diagnosiging if a packet is reaching to a destination
  client or a server.

* Network Layers

The layered network model is often called a *network stack* or the
*TCP/IP* stack.

** Common network layers

- OSI (Open Systems Interconnect) seven layer model: More academic
  than real world.
- TCP/IP: Better fit for modern networks but lacks the details of the
  OSI model.
- This book: Slightly different.

** Layer 1: Physical

- Physical layer is the wire, although it can be radio waves or
  coaxial cable or any number of things other than a typical Ethernet
  wire.
- Most servers connect to a network via an Ethernet cabale, usually
  over a [[https://en.wikipedia.org/wiki/Category_5_cable][Cat5]] or [[https://en.wikipedia.org/wiki/Category_6_cable][Cat6]] cable but sometimes over optical fiber.
- Even non Ethernet protocol such as Asynchronous transfer mode (ATM)
  or Token ring or FDDI will probably use cat5 or cat6 or optical
  fiber.
- Physical layer traditionally has no intelligence.

** Layer 2: Datalink

- The datalink layer transforms the network's upper layers into the
  signals transmitted over the wire.
- Most environment use Ethernet as the datalink layer. A single lump
  of datalink is called a *frame*.
- If you're running IPv4, the datalink layer includer includes Media
  Access Control (MAC) and the Address resolution protocol (ARP). IPv6
  uses MAC addresses and Neighbor discover (ND).

** Layer 3: Network

- Network layer maps connectivity between hosts.
- A single lump of network data is called a *packet*
- The Internet uses the Internet protocol or IP. All versions of IP
  give each host one or more unique IP addresses.

** Layer 4: Transport

- The data you care about flows at the transport layer
- A piece of transport layer data is a *segment*
- Most common transport layer protocols:
  - Internet Control Message Protocl (ICMP)
  - Transmission Control Protocl (TCP)
  - User Datagram Protocl (UDP)

*** ICMP

- Handles low level connectivity messages between hosts.
- Every host that implements IP must also support ICMP.
- ping are the most commonly known type of ICMP traffic, although many
  core Internet functions rely on ICMP.
- If a datalink-layer message is too large, the complaint passes over
  ICMP.
- ICMP is where hosts repsond to ping requests and tell traffic to go
  around the other way.
- Unilaterly blocking all ICMP is a good way to break applications.
- Most of the time, ICMP runs silently in the background

*** UDP/TCP

- Both UDP and TCP carray application data between hosts.
- They are so commona that the suite of internete protocls is usually
  called TCP/IP.
- Usually when using UDP, the reliability is handled in the
  application rather than the network.
- TPC includes error checking, congestion control and retransmission
  of lost dta.

** OSI layers

- According to OSI model the next layers are session, presentation and
  application.
- The session layer handles opening, using and closing transport layer
  connections.
- The presentation layer lets program exchange data with one another.
- The application layer is the actual protocol spoken over these
  connections.

** TCP/IP model

- This model calls everything above the transport layer the
  application layer. This includes protocols like HTTP, SMTP, LDAP
  etc.

* Layering in Practice

- What happens when you open your web browser and call up a web page ?
  - Transport layer in the OS kernel takes the request and slices it
    into chunks small enough to fit into TCP segments (536 bytes or
    smaller). It hands these segments down to the network layer.
  - The network layer only cares about where the segment needs to
    go. If the network layer knows how to reach the destination
    address it wraps each segments with IP information to create a
    package and hands the packet off to the datalink layer.
  - The datalink layer doesn't know about IP address, let alone web
    browsers. It only knows how to launch packets at a particular MAC
    adddresses. This layers adds information for the physical protocol
    to the packet, creating a frame and sends it across the wire.
  - The wire carries the frame to the destination, where the target
    computer strips off the layers, reassembles the request and hands
    it up to the web server. The web server processes the request and
    returns a response, which takes the same journey back.

* Layers and Troubleshooting

- If a lower level fails, all the layers above it also
  fail. Troubleshooting the upper layer might indicate an error, but
  won't expose the actual problem.

  lists the other Ethernet addresses that your OS sees on the network.

** Network troubleshooting

- Usualy tools like *ping* or *traceroute* are used.

** Tranport troubleshooting

- Use *netstat* to view established connections.
- Use *netcat* to see if you can transmit data to another host.
- Try *tcpdump* to see if data arrives at your server and verify your
  host is actually sending data.

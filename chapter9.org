- A packet sniffer displays packets as they cross a network interface.
- The sniffer can capture and display everything that arrives from the
  network adn everything that leaves the server.
- Packet sniffers have sophiticated fileters that let you select
  exactly what traffic you capture and display, so you can narrow in
  on what you're looking for.

* Packet Sniffers

- Solaris: snoop
- Microsoft: Network Analyzer
- Unix: tcpdump and Wireshark

** tcpdump

- Available for almost all the OS
- The filtering language created for tcpdump, Berkeley Packet Filter
  (BPF) syntax has become a standard part of networking.
- Almost every packet sniffer supports tcpdump style BPF expressions,
  so tcpdump education is portable.
- Port of tcpdump for Windows: WinDump. It requires WinPcap library
  and drivers.
- One popular use of tcpdump is to capture traffic to a file for
  analysis on a different machine.

** Wireshark

- Much largeer than tcpdump
- It's a traffic analysis tool
- Should never go into production

** Packet Sniffer Security

- All packet sniffers attach to a network interface at a low level. So
  they need administrative privileges to run.
- Modern operating systems run tcpdump in a sandbox to prevent
  security issues.

** Packet Sniffer Interfaces

- When you run a packet sniffer, you must decide which interface to
  sniff on, or attach.
- Many systems have only one physical network interface, but you might
  have multiple virtual interfaces and tunnels, not to mention the
  loopback interface.

** Encryption and Packet Sniffers

- A packet sniffer can trivially capture usernames and passwords from
  unencrypted traffic.

* Using tcpdump

** Identifying Interfaces

#+begin_src sh :exports both :eval never-export :results verbatim
tcpdump -D | head -n 3
#+end_src

: 1.wlp0s20f3 [Up, Running]
: 2.any (Pseudo-device that captures on all interfaces) [Up, Running]
: 3.lo [Up, Running, Loopback]

#+end_example

** Reading UDP Packets

#+begin_example
18:33:47.906881 IP _gateway.domain > arya.43741: 33446 NXDomain 0/0/1 (53)
#+end_example

- First field is a timestamp at 47.906881 seconds.
- Second field IP shows that this is an IP packet. You'll see other
  protocols here like IP6, 802.1 etc.
- Third field is the IP address or hostname that is the source of the
  packet. The packet came from the _gateway.domain.
- The arrow indicates that this packet is moving on to another host.
- The destination host is arya on port 43741. (which is my localhost)

If tcpdump understands the packet, it prints the packet contents at
the end. It seems in my case it's something lelated to DNS query.

You can run *tcpdump* by disabling DNS queries using the /-n/ option.

** Reading TCP Packets

*** TCP flags in tcpdump

#+begin_example
18:33:47.895675 IP 172.65.251.78.https > arya.48304: Flags [.], ack 116, win 1229, length 0
#+end_example

- The presence of a *Flags* value in the line tells you that this is a
  TCP packet. It shows the state of a connection. The flags are:
  - S: means SYN packet.
  - .: period is an ACK or an acknowledgement.
  - R: TCP reset.
  - F: FIN packet.

* Filtering Captuers

** Filter Format

- Tcpdump filters uses keywords and variables.
- Logical operators: and, not, or and parenthesis.

Syntax:

#+begin_example
tcpdump -n -i interface filter-expressions
#+end_example

* Capture Files

- Tcpdump can copy all the packets it captures to a file.
- It's a binary dump of the actual packets.
- You can read a capture file with tcpdump, another packet sniffer or
  sent it to an expert.
- Capture files can contain sensitive information. Any authentication
  information that's sent unecrypted will appear in plain text inside
  the capture file.

** Capturing to a File

- Specify a cpature file with /-w/ and the filename.
- Traditionally, a capture files end in *.pcap*

#+begin_example
$ tcpdump -w dns.pcap -ni 1 udp port 53
tcpdump: listening on wlp0s20f3, link-type EN10MB (Ethernet), capture size 262144 bytes
^C10 packets captured
10 packets received by filter
0 packets dropped by kernel
#+end_example

You can check the file:

#+begin_example
$ ls -lh dns.pcap
-rw-r--r-- 1 root root 1.5K Apr 29 20:05 dns.pcap
#+end_example

* TCP/IP

- TCP is a specific transport protocol that runs over IP but the name
  *TCP/IP* referes to the whole family of protocols related to TCP and
  IP: ICMP, UDP and TCP itself along with less common protocls like
  SCTP etc.

* ICMP

- ICMP transimits availability, routing and status messages.
- It's best know for tools like ping, traceroute. But it includes all
  sorts of different messages.

* UDP

- UDP is the most minimal transport protocol availalbe in TCP/IP.
- The protocol considers each UDP packet self-contained and while each
  packet has its own checksum, the procol doesn't do anything to
  verify a flow of data as an entity.
- UDP is used for applications that do their own data flow error
  management.
- Example applications: VoIP, VPNs

* TCP

- The TCP includes much of the error connection that UDP lacks. The
  receiver acknowledges every single packet it receives. The sender
  retransmits any packet that isn't acknowledged. The packets have a
  very specific order, and the OS verifies the integrity of the data
  stream.
- Host exchanging TCP data must setup a connection for the data to
  flow across. One host request a connection. The destination host
  either accepts, rejects or ignores the request. If the destination
  accepts the request, it sends back information on how to
  connect. When the first host acknowledes the receipt of that
  information, it can start transmitting actual data. This setup
  process is called the *three way handshake*. Similarly, once both
  hosts finish with the connection they must go through a littlance
  dance to tear it down, the *four-way handshake*.

* Protocol rules and Troubleshooting

** Logical Ports

- TCP and UDP both use *logical ports* to multiplex connections
  between machines, permitting one host to serve many different
  services to many hots.
- When a network service like a web server starts it attaches or
  *binds* to one ore more logical ports.
- A logical port is a number between 0 and 65535. TCP and UDP logical
  ports are separate things, although they use the same range of port
  numbers.

** Source and Destination Ports

- Every connection comes from a port and goes to a port. If your
  desktop wants to connect to a service on a server, it picks a high
  numbered port on the desktop and sends a packet to the service's
  port on the server.
- The unique combination of ports and IP address permits multiplexing
  of connections.
- Clients normally originate connections from high numbered ports not
  assigned for other purposes. IANA recommends using port numbers
  49,152 to 65,532 for these *ephemeral ports*.

** Combining Ports and IP Addresses

- IPv4: IP address, a colon and the port. Example: 192.0.2.66:80
- IPv6: Uses square brackets [38:ba:f8:2a:33:57]:80
  - But caveat: Nobody respects the standard!

** The Services File

- Unix: /etc/services
- Windows: C:\\Windows\System32\drivers\etc\services

- Service files list services commonly used on the machine and the
  logical TCP and UPD port they normally use.

** Sockets

- A socket is communciation endpoint for a process. It's a virtual
  connection for plugging communication into.
- Sockets are used in places besides the network. Both Windows and
  Unix have local sockets which are system entities on the filesystem
  or in memory that accept connections from other programs.
- In TCP/IP, a socket listens for network connection. Unlike a
  physical socket, a network socket can accept any number of
  connections as long as all the clients have unique source IP
  addresses and ports.

** Network Daemons and the Root User

- Most Unix systems only permit the root account to open TCP and UDP
  ports below 1024.
- Unprivileged users can run servers on higher port numbers.
- Running software on a newtork as root user isn't a good idea. Duh!

* TCP Connection state

** The Three-Way Handshake

- First stage: a *SYN* request or *SYN_SENT* is sent when a client
  requests a TCP connection from a server. This requests comes from a
  random high numbered port on the client and goes to a specific port
  on the server.
- Second stage: The server responeds to the *SYN* request with
  *SYN-ACK*. The response comes from the requested port on the server
  and goes to the client's source port.
- Third stage: The client sends *ACK* acknoleding the server's
  synchronization request.

After the above handshake, the connection is *ESTABLISHED*. The client
and server can exchange data as long as they can maintain a
connection.

When the servers finish exchanging data, both sides request and
acknowledge teardown. This is where you get states like *CLOSE_WAIT,
TIME_WAIT, FIN_WAIT_2* and *LAST_ACK*.

** TCP Failures

Some of the problems:

- Connect stuck in *SYN* or *SYN_SENT* states.
- Client or server may send a TCP reset message. This means "I'm
  losing control of this connection, throw away immediately". (This
  most likely is caused by a server side error)
